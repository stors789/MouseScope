# MouseScope v2.0.0 升级计划

## 1. 目标

在现有 `TST`、`OFT`、`NOR` 三个模块不被破坏的前提下，为 MouseScope 新增两个行为学实验模块：

- `EPM`：高架十字迷宫 Elevated Plus Maze
- `Y-Maze`：Y 迷宫自发交替 Spontaneous Alternation

同时满足以下约束：

- 全程沿用当前项目的 Flask + OpenCV + 本地浏览器 GUI 架构
- 不破坏现有模块的上传、标定、监控、下载和手册系统
- 兼容当前中英文切换机制
- 继续使用 UTF-8 / UTF-8-SIG，避免中文乱码
- 保留当前“每视频独立配置”的批量工作流
- 新模块需要补齐使用手册与版本文档

## 2. Protocol 调研结论

### 2.1 EPM

综合参考：

- protocols.io: `Elevated plus maze test for mice` (2024)
- MDPI / IJMS 2025 文中 `4.5.3 Elevated Plus Maze`
- ANY-maze Elevated Plus-maze 指南

核心实验逻辑：

- 装置由 `2 个开放臂 + 2 个闭合臂 + 中心区` 组成，常见中心区约 `5 x 5 cm`
- 小鼠置于中心区开始，自由探索固定时长，常见 `5 min` 或 `10 min`
- 焦虑样行为越强，通常 `开放臂停留时间更少`、`开放臂进入更少`
- 常用指标：
  - 开放臂时间 / 闭合臂时间 / 中心区时间
  - 开放臂进入次数 / 闭合臂进入次数
  - 开放臂时间百分比
  - 开放臂进入百分比
  - 首次进入开放臂潜伏期
  - 总路程

工程实现含义：

- 软件必须能稳定区分 `center / open / closed`
- 需要对“进入 arm”的判定做一个尽量接近传统规则的近似
- 输出里既要有绝对时间，也要有比例指标

### 2.2 Y-Maze

综合参考：

- protocols.io: `Y-Maze Protocol` (2024)
- Bio-Protocol / IJMS 中的 spontaneous alternation 描述
- ANY-maze spontaneous alternation 指南

核心实验逻辑：

- 装置由 `3 个臂` 构成，通常互成 `120°`
- 小鼠自由探索，常见 `5 min` 或 `8 min`
- `arm entry` 的传统定义是“全身进入臂内，尾巴除外”或“all four paws in arm”
- `spontaneous alternation` 定义为：连续 `3` 次 arm entry 都落在不同的臂
- 常用指标：
  - 总 arm entries
  - 各 arm 进入次数
  - 自发交替次数
  - 自发交替率 `% alternation = alternations / (total arm entries - 2) * 100`
  - 各 arm / 中心区停留时间
  - 总路程

工程实现含义：

- 软件必须有可靠的 `arm entry sequence`
- 需要保存 arm entry 序列并实时计算 triad alternation
- 监控页和 summary 要把 `alternation_count / alternation_rate / opportunities` 明确显示出来

## 3. 实现策略

### 3.1 总体原则

尽量复用现有 `OFT/NOR` 的成熟模式：

- 上传页选择实验类型
- 独立标定页
- 独立监控页
- `app.py` 中独立分析 session
- `core/` 中独立 tracker / 渲染 / 出图模块
- CSV / TXT / 热图 / 轨迹图 / 标注视频的统一导出方式

### 3.2 EPM 标定方案

采用“每个 zone 独立手动画”的方式：

- 用户为每个 ROI 依次绘制：
  - `中心区`
  - `开放臂 1 / 2`
  - `封闭臂 1 / 2`
- 每个区域用 `4 个角点` 框定，角点顺序在前端和后端都会自动归一化
- 输入：
  - 中心区边长 `center_size_cm`
  - 开放臂长度 `open_arm_length_cm`
  - 闭合臂长度 `closed_arm_length_cm`
- 软件直接按手画 polygon 判区，并通过手画边长与真实尺寸估算平均 `cm/px`

### 3.3 Y-Maze 标定方案

采用“中心区 + 三臂独立手画”的方式：

- 用户为每个 ROI 依次绘制：
  - `中心区`
  - `Arm A / B / C`
- 每个区域用 `4 个角点` 框定，点击顺序自动归一化
- 输入：
  - 臂长 `arm_length_cm`
  - 臂宽 `arm_width_cm`
- 软件直接按手画 polygon 判区，并按臂长/臂宽估算平均 `cm/px`

优点：

- 标定交互足够轻量
- 便于自动生成规范化热图、轨迹图和 arm zone
- 适合 spontaneous alternation 的标准化 arm 识别

### 3.4 追踪与统计底层

新模块将采用“图像坐标检测 + 手画 polygon 统计”的方案：

- 检测阶段：
  - 继续复用当前的背景减除、阈值分割、形态学和鼠体轮廓检测
- 尺度阶段：
  - 基于手画边长与真实装置尺寸估算平均 `cm/px`
- 分区阶段：
  - EPM: `center / open_left / open_right / closed_top / closed_bottom`
  - Y-Maze: `center / arm_a / arm_b / arm_c`
- 统计阶段：
  - 时间、比例、进入次数、速度、距离、潜伏期、分箱
  - Y 迷宫额外做 arm entry 序列与 alternation 计算

### 3.5 关于“arm entry”近似

协议里常见定义是 `all four paws in arm` 或 `full body minus tail in arm`。  
当前项目基于传统视觉和质心追踪，不适合直接做高精度足部检测，因此计划采用：

- 在每个手画 arm polygon 内部建立一个“进入深区”
- 只有当鼠体质心越过该阈线，才记为一次 arm entry

这样可以尽量避免中心区边界抖动造成的伪 entry，并更接近传统行为学人工评分逻辑。  
手册里会明确说明这是软件实现上的近似规则。

## 7. 风险与防护

### 7.1 不破坏现有模块

- 只新增分支，不重写旧模块主逻辑
- 旧 `TST/OFT/NOR` 的模板、session、tracker 尽量不动
- 所有旧路由继续保持原行为

### 7.2 中文编码

- 所有新文件统一保存为 UTF-8
- CSV 继续保持 `utf-8-sig`
- 视频叠字如需中文，沿用当前 `NOR` 的 Unicode 文本绘制策略

### 7.3 中英切换

- 公共导航与入口文字进入 `i18n.js`
- 模块内部复杂手册/页面文案，可继续采用模块内局部字典模式

### 7.4 验证

实现后至少做：

- `python -m compileall` 级别语法检查
- Flask 启动级别 import 检查
- 新旧 5 个模块的路由可达性检查
- 关键 session 创建与 payload 结构检查
