# MouseScope v3.0.0 实验项目工作台规划

## 0. 背景与判断

MouseScope v2.3.0 已经具备 6 类实验的统一上传、配置、批量、监控、历史记录与结果目录管理能力。当前主要工作流仍然以“视频分析任务”为中心：用户上传视频，完成 ROI / zone / 参数配置，启动分析，然后在任务中心和结果目录里找结果。

这个模式适合临时分析，但真实实验室通常不是按“单个视频文件”组织数据，而是按：

- 项目 / 课题
- 组别
- 小鼠编号
- 实验类型
- 日期 / 批次 / 时间点
- 视频与结果

来组织。用户最终也不是只看一个视频的 summary，而是想得到一张可以直接进入 Prism、Excel、R 或 Python 的项目总表。

因此，`实验项目工作台 Project Workspace` 应成为下一阶段主线。它不是新增第七个实验模块，而是在现有 6 个分析模块之上增加一层项目级数据组织、分析调度、结果归档与质控汇总。

## 1. 产品定位

本功能明确面向 `桌面单机版` MouseScope。项目、组别、小鼠、视频、分析和结果都以本机文件夹和本地数据库为中心，不引入账号体系、多人协作、权限分级、云端同步或审计流。

### 1.1 一句话目标

把 MouseScope 从“逐视频分析工具”升级为“按项目组织的行为学实验数据工作台”。

### 1.2 核心价值

- 用户可以先创建项目，固定组别、小鼠信息和实验计划。
- 视频导入后可以绑定到小鼠、组别、实验类型和时间点。
- 分析完成后，结果自动回写到项目，而不是只散落在输出目录。
- 项目结果中心可以按小鼠、组别、实验类型汇总指标。
- 后续的质控报告、跨实验汇总、组间导出都会有可靠的数据来源。

### 1.3 必须保留的旧入口

项目模式是增强，不是替代。

MouseScope 必须同时保留：

1. `快速分析入口`
   - 适合临时跑一个视频或一个小批次。
   - 不要求创建项目。
   - 继续走现有上传页、配置页、任务中心。

2. `项目工作台入口`
   - 适合正式实验、长期项目、多组别、多小鼠、多实验类型。
   - 以项目为单位组织视频、分析和结果。

如果强迫用户为了跑一个临时视频也必须先建项目，产品会变重，反而不适合真实使用。

## 2. 用户场景

### 2.1 正式实验项目

用户准备一个药效实验：

- Control 组 12 只
- Model 组 12 只
- Drug-Low 组 12 只
- Drug-High 组 12 只

每只小鼠做：

- OFT
- NOR
- EPM
- Y-Maze

项目工作台应支持：

- 提前录入组别和小鼠编号。
- 批量导入视频。
- 将视频绑定到实验类型和小鼠。
- 按实验类型分批启动分析。
- 分析完成后自动生成项目级汇总。

### 2.2 单视频多 ROI / 多小鼠场景

部分实验视频可能一帧里包含多个 ROI，例如：

- TST 多只小鼠同屏悬尾
- FST 多个圆筒同屏
- OFT / NOR 多 arena 同屏

项目模型不能简单假设“一个视频等于一只小鼠”。必须允许：

- 一个视频对应一个或多个 `分析单元`
- 每个分析单元绑定一个小鼠
- 分析单元可对应 ROI、arena、cylinder 或 maze zone set

第一阶段可以默认“一视频一小鼠”，但数据模型必须能升级到“一视频多分析单元”。

关键交互应复用现有配置页里的 ROI / arena / cylinder 命名入口。快速分析模式下，ROI 名称仍然可以是自由文本；项目模式下，ROI / arena / cylinder / maze unit 的“名称”应优先变成项目小鼠下拉选择。用户在项目里先确定小鼠列表，进入配置页后，每个分析单元从已登记小鼠中选择绑定对象。

这个方案比从视频文件名推断小鼠更可靠：

- 用户已经在项目中确认过小鼠编号和组别。
- 配置页本来就是确定 ROI / arena 归属的位置。
- 多 ROI 同屏时，每个 ROI 可以独立绑定一只小鼠。
- 后续结果汇总可以直接依赖 `subject_id`，而不是解析 ROI 文本或文件名。

原则上，ROI 显示名可以自动使用小鼠编号，但项目数据库不能只保存显示名，必须同时保存结构化字段，例如 `unit_id`、`subject_id`、`animal_code`、`group_id` 和 `group_name`。

### 2.3 结果复核与排除

用户完成分析后，项目结果中心应显示：

- 这个小鼠每个实验是否完成
- 结果文件是否存在
- 检测率是否太低
- uncertain 时间是否太高
- 是否需要回看标注视频
- 用户是否手动标记“排除”或“已复核”

这会让项目结果不只是“能导出”，而是“知道哪些结果能不能信”。

## 3. 范围与非目标

### 3.1 v3.0.0 建议范围

v3.0.0 建议做 `Project Lite`，目标是把项目主干跑通：

- 项目列表与新建项目
- 项目信息编辑
- 组别管理
- 小鼠管理
- 视频导入与视频元数据索引
- 视频绑定实验类型 / 小鼠 / 组别
- 从项目中启动现有单实验批量分析
- 分析结果回写项目
- 项目结果列表与基础导出

### 3.2 v3.0.0 暂不做

以下能力很有价值，但不建议第一版就做满：

- 自动统计显著性检验
- 自动生成论文级图表
- 数据库复杂迁移 UI
- 自动识别视频文件名里的所有元数据
- 完整 LIMS 系统

以下能力不属于 MouseScope 单机版目标，后续也不作为主线规划：

- 多用户账号
- 多用户权限
- 云同步
- 在线协作
- 服务器部署

原因：项目工作台本身会改动数据模型、页面结构和分析启动流。第一版先确保基础模型稳定，再叠加高级报告。

## 4. 总体信息架构

新增顶部导航入口：

- `项目`

项目相关页面建议分为：

1. `项目列表`
   - 新建项目
   - 打开项目
   - 最近更新
   - 项目根目录

2. `项目首页`
   - 项目概览
   - 组别数量
   - 小鼠数量
   - 视频数量
   - 分析完成度
   - 质控风险数量

3. `项目设置`
   - 项目名称
   - 描述
   - 默认输出位置
   - 默认实验日期
   - 备注

4. `组别与小鼠`
   - 组别增删改
   - 小鼠增删改
   - CSV 导入小鼠表
   - 小鼠所属组别、性别、品系、笼号、备注

5. `视频库`
   - 导入视频
   - 查看视频元信息
   - 绑定实验类型
   - 绑定小鼠 / 分析单元
   - 标记是否已配置 / 已分析

6. `分析`
   - 按实验类型筛选待分析视频
   - 创建项目分析批次
   - 进入现有配置页 / 批量工作台
   - 查看运行中的分析

7. `结果`
   - 按实验类型查看 summary
   - 按小鼠查看跨实验结果
   - 按组别查看结果完成度
   - 基础质控标记
   - 打开结果目录
   - 导出 CSV / Excel

## 5. 数据模型设计

### 5.1 存储策略

建议采用“中心索引 + 项目目录”的方式。

中心索引：

- `data/projects/project_index.sqlite`
- 只保存项目列表、项目路径、最近打开时间、删除状态等轻量信息。

每个项目一个项目目录：

```text
data/projects/
  project_index.sqlite
  PRJ_20260509_ab12_MemoryStudy/
    project.sqlite
    videos/
    results/
    exports/
    thumbnails/
```

项目内部数据库：

- `project.sqlite`
- 保存组别、小鼠、视频、分析单元、分析记录、结果指标、质控标记。

这样做的好处：

- 项目可以作为一个文件夹整体备份。
- 结果目录天然属于项目。
- 以后允许用户选择项目根目录。
- 中心索引损坏时，项目目录仍有独立数据库可恢复。

### 5.2 视频文件策略

视频文件通常很大，不建议默认复制。

视频导入提供两种模式：

1. `引用原始路径`
   - 默认模式。
   - 只记录源文件路径和基本元信息。
   - 优点：不占额外空间。
   - 风险：源视频被移动后需要重新定位。

2. `复制到项目视频库`
   - 可选模式。
   - 将视频复制到 `project/videos/`。
   - 优点：项目可整体备份。
   - 风险：占用大量磁盘空间。

第一版建议默认引用路径，并在 UI 上明确显示“源文件存在 / 源文件缺失”。

### 5.3 核心表结构草案

#### projects index

```sql
CREATE TABLE project_index (
    project_id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    project_dir TEXT NOT NULL,
    description TEXT,
    created_at REAL NOT NULL,
    updated_at REAL NOT NULL,
    last_opened_at REAL,
    archived INTEGER NOT NULL DEFAULT 0
);
```

#### project_meta

```sql
CREATE TABLE project_meta (
    key TEXT PRIMARY KEY,
    value TEXT
);
```

建议保存：

- `project_id`
- `name`
- `description`
- `default_output_dir`
- `created_at`
- `updated_at`
- `schema_version`

#### project_groups

```sql
CREATE TABLE project_groups (
    group_id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    color TEXT,
    sort_order INTEGER NOT NULL DEFAULT 0,
    notes TEXT,
    created_at REAL NOT NULL,
    updated_at REAL NOT NULL
);
```

#### project_subjects

```sql
CREATE TABLE project_subjects (
    subject_id TEXT PRIMARY KEY,
    animal_code TEXT NOT NULL,
    group_id TEXT,
    sex TEXT,
    strain TEXT,
    genotype TEXT,
    cage_id TEXT,
    birth_date TEXT,
    age_label TEXT,
    weight_g REAL,
    notes TEXT,
    active INTEGER NOT NULL DEFAULT 1,
    created_at REAL NOT NULL,
    updated_at REAL NOT NULL,
    FOREIGN KEY(group_id) REFERENCES project_groups(group_id)
);
```

约束建议：

- `animal_code` 在项目内唯一。
- `group_id` 可以为空，便于先导入小鼠再分组。

#### project_videos

```sql
CREATE TABLE project_videos (
    video_id TEXT PRIMARY KEY,
    original_name TEXT NOT NULL,
    source_path TEXT NOT NULL,
    project_path TEXT,
    storage_mode TEXT NOT NULL DEFAULT 'linked',
    path_exists INTEGER NOT NULL DEFAULT 1,
    sha1 TEXT,
    fps REAL,
    width INTEGER,
    height INTEGER,
    total_frames INTEGER,
    duration_s REAL,
    imported_at REAL NOT NULL,
    updated_at REAL NOT NULL,
    notes TEXT
);
```

`project_path` 只在复制到项目视频库时使用。

#### experiment_assignments

这个表表示“某个视频要做某个实验”。

```sql
CREATE TABLE experiment_assignments (
    assignment_id TEXT PRIMARY KEY,
    video_id TEXT NOT NULL,
    experiment_type TEXT NOT NULL,
    session_label TEXT,
    day_label TEXT,
    trial_no INTEGER,
    planned_at REAL,
    status TEXT NOT NULL DEFAULT 'pending',
    latest_run_id TEXT,
    notes TEXT,
    created_at REAL NOT NULL,
    updated_at REAL NOT NULL,
    FOREIGN KEY(video_id) REFERENCES project_videos(video_id)
);
```

`status` 建议取值：

- `pending`
- `configured`
- `analyzing`
- `completed`
- `error`
- `excluded`

#### assignment_units

这个表表示视频里的分析单元。它解决“一视频多小鼠 / 多 ROI”的问题。

```sql
CREATE TABLE assignment_units (
    unit_id TEXT PRIMARY KEY,
    assignment_id TEXT NOT NULL,
    subject_id TEXT,
    group_id TEXT,
    unit_label TEXT,
    roi_index INTEGER,
    roi_name TEXT,
    role TEXT,
    include_in_export INTEGER NOT NULL DEFAULT 1,
    manual_qc_status TEXT,
    notes TEXT,
    created_at REAL NOT NULL,
    updated_at REAL NOT NULL,
    FOREIGN KEY(assignment_id) REFERENCES experiment_assignments(assignment_id),
    FOREIGN KEY(subject_id) REFERENCES project_subjects(subject_id),
    FOREIGN KEY(group_id) REFERENCES project_groups(group_id)
);
```

说明：

- 单视频单鼠时，默认创建一个 unit。
- 多 ROI 时，每个 ROI 对应一个 unit。
- `roi_index` 和 `roi_name` 用于和 summary.csv 的 ROI 行做映射。
- `role` 用于 NOR 等需要记录 familiar / novel 或特殊对象角色的场景。第一版可先保留字段不复杂使用。
- 项目模式下，配置页保存 ROI / arena / cylinder / maze unit 时，应把所选小鼠写入 `subject_id` 和 `group_id`；`roi_name` 可以同步为 `animal_code`，但不能作为唯一绑定依据。
- 同一 assignment 内默认不允许多个 unit 绑定同一个 `subject_id`，除非用户显式确认这是重复 trial 或特殊设计。
- 允许 unit 暂时未绑定小鼠，但项目分析启动或项目结果导出前必须明确提示未绑定项。

#### project_runs

项目里的分析记录。它连接项目和现有任务中心 / 分析历史。

```sql
CREATE TABLE project_runs (
    project_run_id TEXT PRIMARY KEY,
    run_id TEXT NOT NULL,
    session_id TEXT NOT NULL,
    experiment_type TEXT NOT NULL,
    assignment_ids TEXT NOT NULL DEFAULT '[]',
    output_dir TEXT,
    status TEXT NOT NULL,
    progress INTEGER NOT NULL DEFAULT 0,
    message TEXT,
    created_at REAL NOT NULL,
    updated_at REAL NOT NULL,
    finished_at REAL,
    result_files TEXT NOT NULL DEFAULT '[]'
);
```

#### result_metrics

项目结果中心可先用 JSON 存指标，避免第一版为每种实验建不同宽表。

```sql
CREATE TABLE result_metrics (
    metric_id TEXT PRIMARY KEY,
    project_run_id TEXT NOT NULL,
    assignment_id TEXT,
    unit_id TEXT,
    subject_id TEXT,
    group_id TEXT,
    experiment_type TEXT NOT NULL,
    source_file TEXT,
    metrics_json TEXT NOT NULL DEFAULT '{}',
    qc_json TEXT NOT NULL DEFAULT '{}',
    include_in_export INTEGER NOT NULL DEFAULT 1,
    created_at REAL NOT NULL,
    updated_at REAL NOT NULL,
    FOREIGN KEY(project_run_id) REFERENCES project_runs(project_run_id)
);
```

后续如果导出速度或查询复杂度成为问题，再按实验拆派生宽表。

### 5.4 analysis_history 扩展

现有 `AnalysisHistoryStore` 仍然是任务中心的权威来源。项目模式不应绕开它。

建议给 `analysis_runs` 增加可空字段：

- `project_id`
- `project_name`
- `project_run_id`
- `assignment_ids`

旧记录这些字段为空，不影响现有功能。

如果不想第一阶段改历史库 schema，也可以先把项目上下文写入 `config_summary` JSON。但长期更建议有显式字段，方便任务中心按项目筛选。

## 6. 服务层设计

### 6.1 新增服务模块

建议新增：

```text
services/
  project_store.py
  project_imports.py
  project_analysis_bridge.py
  project_results.py
  project_qc.py
```

#### project_store.py

职责：

- 项目索引管理
- 项目创建 / 打开 / 归档
- 项目数据库初始化和迁移
- 组别 CRUD
- 小鼠 CRUD
- 视频 CRUD
- assignment / unit CRUD

不要把分析启动逻辑塞进 `ProjectStore`。

#### project_imports.py

职责：

- 视频导入
- 视频元信息读取
- CSV 小鼠表导入
- CSV 视频映射表导入
- 文件名解析建议

文件名解析只能作为“建议”，不能作为唯一事实来源。

#### project_analysis_bridge.py

职责：

- 从项目 assignment 创建现有 `SessionStore` session。
- 将项目上下文写入 session。
- 设置项目默认 output_dir。
- 将分析启动后的 run_id / session_id 回写 project_runs。
- 在分析完成后同步 `AnalysisHistoryStore` 和 `ProjectStore`。

这个桥接层是项目功能和现有分析系统之间的关键隔离层。

#### project_results.py

职责：

- 从 result_files 或 output_dir 扫描 summary.csv / immobility.csv。
- 解析不同实验的结果表。
- 根据 assignment_units 映射到小鼠和组别。
- 写入 result_metrics。
- 提供项目结果查询和导出。

#### project_qc.py

职责：

- 按实验类型执行基础质控规则。
- 给 result_metrics 写入 qc_json。
- 汇总项目级风险数量。

## 7. 与现有分析流程的衔接

### 7.1 不改 core 分析器

第一阶段尽量不改：

- `core/vision_tracker.py`
- `core/forced_swim.py`
- `core/open_field.py`
- `core/novel_object.py`
- `core/elevated_plus.py`
- `core/y_maze.py`

项目功能应通过 session、history 和 result parser 接入，而不是让底层算法知道“项目”的存在。

### 7.2 SessionStore 增加 project_context

项目启动分析时，创建的 session 建议包含：

```python
{
    "project_context": {
        "project_id": "...",
        "project_name": "...",
        "project_run_id": "...",
        "assignment_ids": ["..."],
        "video_assignment_map": {
            "0": "assignment_id_1",
            "1": "assignment_id_2"
        },
        "unit_map": {
            "assignment_id_1": [
                {
                    "unit_id": "...",
                    "subject_id": "...",
                    "animal_code": "...",
                    "group_id": "...",
                    "group_name": "...",
                    "roi_index": 0,
                    "roi_name": "Mouse01"
                }
            ]
        }
    }
}
```

现有 builder 和 analysis session 可以忽略这个字段。项目桥接层和结果解析层使用它。

### 7.3 项目模式下的 ROI / 小鼠绑定

项目模式进入现有配置页时，页面应获得 `project_context` 中的小鼠候选列表，并调整 ROI / arena / cylinder / maze unit 卡片的命名区域：

快速分析模式：

```text
ROI 名称: [自由输入]
```

项目模式：

```text
小鼠 / 实验单元: [M001 · Control ▼]
显示名: M001
```

保存配置时，每个 ROI 应尽量写入：

```json
{
  "name": "M001",
  "project_unit_id": "unit_xxx",
  "subject_id": "subject_xxx",
  "animal_code": "M001",
  "group_id": "group_control",
  "group_name": "Control"
}
```

不同实验的对应关系：

- TST：每个 ROI 绑定一个小鼠。
- FST：每个 cylinder ROI 绑定一个小鼠。
- OFT：每个 arena ROI 绑定一个小鼠。
- NOR：每个 arena ROI 绑定一个小鼠，物体仍然属于该 ROI 的内部配置。
- EPM：每套 maze zone 绑定一个小鼠。
- Y-Maze：每套 maze zone 绑定一个小鼠。

项目模式下，启动分析前应校验：

- 项目 assignment 中需要导出的 unit 是否已绑定小鼠。
- 同一视频 / assignment 内是否重复绑定同一只小鼠。
- ROI 名称和小鼠编号是否一致；如果用户手动改了显示名，也不能丢失 `subject_id`。

如果视频库中已经把某个视频绑定到唯一小鼠，进入配置页时可以自动预选该小鼠，减少重复操作。

### 7.4 项目分析启动流程

项目内启动分析的流程：

1. 用户在项目分析页选择某个实验类型，例如 OFT。
2. 页面列出所有 `experiment_type = open_field` 且待分析的视频 assignment。
3. 用户选择一个或多个 assignment。
4. 后端通过 `project_analysis_bridge` 创建普通 MouseScope session。
5. 如果多个视频，进入现有 `batch_workspace`。
6. 用户按现有方式配置 ROI / 参数。
7. 用户启动分析。
8. 分析历史记录写入 `AnalysisHistoryStore`。
9. 项目记录写入 `project_runs`。
10. 分析完成后刷新项目结果索引。

### 7.5 输出目录规则

项目模式默认输出到：

```text
<project_dir>/results/<experiment_type>/<run_id>/
```

批量分析时可以继续按视频分子目录：

```text
<project_dir>/results/open_field/20260509_143000/
  01_Mouse01_OFT/
  02_Mouse02_OFT/
```

如果用户手动指定输出目录，应记录在 project_run 中，但 UI 需要提示“该结果不在项目目录内”。

## 8. 前端页面设计

v3.0.0 的项目模块必须继承当前 MouseScope UI 文档，而不是另起一套后台风格。

### 8.0 UI 实现约束

项目工作台的界面应遵守 `DESIGN.md`、`docs/system_design.md` 和 v2 UI 统一改造计划中已经形成的方向：

- 视觉继续使用暖纸感背景、陶土橙主色、暖中性色边框和轻量阴影，避免新模块突然变成冷色后台。
- 项目页应是桌面软件工作台，不是营销首页；第一屏要直接出现项目、组别、小鼠、视频、分析和结果状态。
- 信息组织以表格、紧凑表单、状态标签、批量操作为主，卡片只用于项目条目、局部面板或重复对象，不做大面积装饰。
- 项目首页顶部显示项目名称、路径和关键动作；下方用概览、组别与小鼠、视频库、分析、结果等页签组织。
- 配置页继续保持现有“左侧画布 / 右侧配置列表 / 顶部步骤”的工作台结构。
- 项目模式下的“小鼠 / 实验单元”选择器应嵌入原 ROI / arena / cylinder / maze unit 卡片，不单独做割裂的新页面。
- 快速分析模式下，ROI 名称仍然是自由输入；只有项目模式才改成项目小鼠选择器。
- 绿色按钮只用于成功、打开文件夹、确认类动作；普通下载、返回、刷新等维持 outline 或次级按钮。
- 移动端只保证可用不崩，主要交互优先服务桌面宽屏和本地文件工作流。
- 不在项目模块引入多用户、权限、云同步、审计、在线协作等云端产品式 UI。

## 9. 结果汇总与质控规则

### 9.1 结果解析策略

不同实验当前导出的结构不完全一致：

- TST：`*_immobility.csv`
- FST / OFT / NOR / EPM / Y-Maze：`*_summary.csv`
- 各实验还可能有 `*_bins.csv`、`*_track.csv`、`*_report.txt`

第一阶段项目结果中心只解析核心 summary：

- TST：immobility summary
- FST：summary
- OFT：summary
- NOR：summary
- EPM：summary
- Y-Maze：summary

track 和 bins 暂时作为复核文件，不进入项目总表。

### 9.2 指标导出形态

项目导出建议提供两种表：

1. `long table`

```text
project_id | animal_code | group | experiment_type | metric_name | metric_value | unit | qc_status
```

适合程序分析。

2. `wide table`

```text
animal_code | group | sex | OFT_total_distance_cm | OFT_center_time_s | NOR_discrimination_index | EPM_open_arm_time_s | YMaze_alternation_percent
```

适合 Excel / Prism。

第一版可以先导出 long table，wide table 第二阶段补。

### 9.3 基础质控规则

建议内置规则：

#### 通用

- 结果文件缺失
- summary 为空
- 视频源文件缺失
- 分析状态不是 completed
- 用户手动标记 exclude

#### TST

- `detected_rate_percent` 低于阈值
- `uncertain_percent` 高于阈值
- 不动时间为 0 或接近总时长
- 阈值字段缺失

#### FST

- `detected_rate_percent` 低
- `uncertain_percent` 高
- 不动时间异常为 0 或接近总时长
- latency 缺失

#### OFT

- `detected_rate_percent` 低
- 总路程异常为 0
- 平均速度异常大
- 中心区比例极端

#### NOR

- 总探索时间低于阈值
- head-direction valid rate 低
- DI / preference index 极端且探索时间很短

#### EPM

- `detected_rate_percent` 低
- unknown zone 时间高
- 开放臂 / 封闭臂进入次数全为 0

#### Y-Maze

- `detected_rate_percent` 低
- unknown zone 时间高
- 总入臂数太低
- 交替率无法计算

阈值第一版可以写死在 `project_qc.py`，后续再做项目级可配置。

## 14. 风险与应对

### 14.1 风险：功能范围膨胀

项目工作台很容易变成 LIMS。

MouseScope 的目标不是替代实验室管理系统，而是服务本机行为学视频分析。项目功能只管理与行为学视频分析直接相关的结构化信息：项目、组别、小鼠、视频、分析、结果和质控。

应对：

- 第一版只做项目、组别、小鼠、视频、分析、结果索引。
- 不做复杂统计。
- 不做账号、权限、多人协作。
- 不做云同步和服务器部署。

### 14.2 风险：一视频多小鼠映射复杂

现有分析结果按 ROI / arena 行输出，项目必须知道哪一行属于哪只小鼠。

应对：

- 数据模型先支持 assignment_units。
- 第一版 UI 可以先做默认单 unit。
- 在项目模式配置页中，把 ROI 命名入口改为“小鼠 / 实验单元”选择器。
- 保存 ROI 时同时保存 `subject_id`、`animal_code`、`group_id` 等结构化字段。
- 第二阶段再增强批量自动映射和复杂重复 trial 支持。

### 14.3 风险：视频文件路径失效

用户可能移动源视频。

应对：

- 记录 path_exists。
- 视频库显示缺失状态。
- 提供重新定位。
- 可选复制到项目目录。

### 14.4 风险：项目结果和任务中心不同步

任务中心删除记录不删除结果文件；项目结果索引可能还在。

应对：

- 项目结果以项目数据库为准。
- 任务中心记录是运行历史，不是项目结果唯一来源。
- 项目结果刷新时重新扫描结果文件。

### 14.5 风险：页面太重

项目工作台会引入大量表格和操作。

应对：

- 按 tab 拆页面。
- 每页只处理一个任务。
- 不做大而全的单页。
- 移动端只保证不崩，主要优化桌面宽屏。

## 17. 建议优先级

如果资源有限，优先顺序应为：

1. 项目 CRUD
2. 组别与小鼠
3. 视频库与 assignment
4. 项目启动现有分析流程
5. 项目结果索引
6. 项目导出
7. 高级 QC 与跨实验 wide table

原因：

- 没有项目和小鼠结构，结果汇总没有可信归属。
- 没有 assignment，项目无法和现有分析流程连接。
- 没有结果索引，项目只是文件管理器。
- 导出和 QC 可以在基础链路跑通后持续增强。

## 18. 初步结论

实验项目工作台值得作为 MouseScope v3.0.0 的主线功能。

它会让现有 6 个实验模块形成一个更完整的科研工作流：

```text
创建项目 -> 录入组别和小鼠 -> 导入视频 -> 绑定实验 -> 分析 -> 质控 -> 项目导出
```

实现时最重要的原则是：

- 不破坏快速分析。
- 不改底层算法。
- 项目只作为组织层和结果层接入。
- 数据模型先支持一视频多分析单元。
- 先做 Project Lite，避免第一版变成庞大 LIMS。
- 始终按桌面单机版设计，不引入账号、权限、云同步或在线协作。
