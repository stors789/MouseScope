# MouseScope v2.0.0 UI 与架构统一重构计划

## 0. 变更前备份与回退策略

由于本轮属于大范围结构性改造，正式动工前先保留一份源码快照，避免重构过程中误改后无法快速回退。

- 当前已创建源码备份压缩包：`backups/mousescope_code_snapshot_20260410_222909.zip`
- 备份内容以源码为主：`app.py`、`core/`、`templates/`、`static/`、`docs/`、说明文档等
- 不把 `data/uploads`、`data/results` 等运行产物打进备份，避免无意义膨胀
- 后续如进入关键里程碑，可再追加阶段性快照，形成“可回退检查点”

## 1. 目标

本次重构的目标不是“换一套皮肤”，而是在**不破坏现有分析功能**的前提下，把 MouseScope 当前 5 个实验模块的界面布局、操作逻辑、视觉语言和配置节奏统一起来，使其满足以下要求：

- 不同实验模块在进入页面后的信息架构一致
- ROI / arena / zone / object / mask / time window 的编辑位置与交互方式尽可能一致
- 批量模式具备独立的批次工作台，不再把批量编排塞进单视频 ROI 页面
- 批量工作台配置支持安全序列化，至少避免软件意外关闭后所有已配置 ROI / 参数全部丢失
- `app.py` 从大一统入口文件降为薄入口，新增实验不再依赖在单文件中持续追加长分支
- 实验元数据、配置构建、调试预览、分析启动和手册入口全部纳入统一注册机制
- 前端共享工作台、共享卡片、共享状态管理与 i18n 机制成型，不再让每个模板各写一套大型内联脚本
- 中英文切换后文案结构一致、无乱码、无布局塌陷
- 新增 EPM / Y 迷宫不会成为“特例页面”，而是并入统一 UI 系统
- 按照 [DESIGN.md](e:\MouseScope_gui\DESIGN.md) 的暖色、编辑感、论文式视觉方向重做页面风格
- 所有已有功能保留，不因美化或重排而失效

## 2. 当前问题梳理

### 2.1 布局不一致

- TST 的 ROI 配置区主要在下方；OFT / NOR / EPM / Y-maze 多数在右侧
- 不同模块的步骤导航样式、标题层级、信息卡片结构不一致
- 调参页中“原图 / 结果图 / 参数卡片 / 状态提示”的排列方式不一致
- 上传页、标定页、监控页之间缺少统一的视觉框架

### 2.2 交互节奏不一致

- OFT / NOR 的 ROI 时间窗在选择 `precise` 后才展开输入
- EPM / Y-maze 当前时间窗输入默认直接显示在 ROI 卡片内
- OFT / NOR 支持额外 detection mask，而 EPM / Y-maze 当前没有等价的遮掩框编辑入口
- 有的页面是“先完成 ROI 再进入调参”，有的页面更像“边画边配”

### 2.3 批量模式逻辑不合理

- 当前多视频上传后会直接跳到同一个 ROI / 调参页，再在页面内部切换视频
- 这会让“批次总览”“单视频编辑”“完成状态检查”三类职责混在一个页面里
- 用户无法在进入编辑前先看到整个批次的完成度、缺项和视频差异
- 各模块模板都各自维护 `videoSelector + videoConfigs + currentVideoIdx`，导致批量逻辑重复、难统一、也更容易出 bug
- 批量分析前的缺项检查只能在“开始分析”时集中报错，缺少提前暴露问题的工作台

### 2.4 配置模型不一致

- TST 使用 `roi.points`
- OFT 使用 `arena_points + detection_points + time_config`
- NOR 使用 `arena_points + object_points + detection_points + time_config`
- EPM / Y-maze 已经进入多 zone 模式，但 UI 仍需要进一步纳入统一配置框架

### 2.5 视觉语言不一致

- 当前主站整体仍偏旧版技术风格
- 新增模块使用了另一套布局语言
- 不同页面的按钮、间距、提示块、信息层次、卡片密度差异较大
- 一些页面仍保留较强的“原型工具味道”，缺少统一的产品级完成度

### 2.6 `app.py` 入口文件过载

- 当前 [app.py](e:\MouseScope_gui\app.py) 约 `4405` 行，已经同时承担启动配置、上传处理、会话管理、5 个实验分析类、模板路由、调试预览、分析启动、结果下载等多种职责
- 新增一个实验时，往往需要同时修改手册映射、模板选择、监控页选择、预览分发、分析启动等多个分散位置
- `if / elif` 型实验分发链过长，未来继续加实验会越来越容易漏改
- `start_analysis` 中各实验 payload 解析与默认值拼装高度重复，是最容易误改的热点区
- 分析 session 类也堆在同一文件中，导致任何页面层改动都必须触碰超长入口文件

### 2.7 前端共享层不足

- `calibrate*.html` 中存在大量大块内联脚本，模块间重复实现视频状态保存、ROI 卡片渲染、时间窗切换、预览请求、批量校验
- 实验名称、手册入口、模板选择、文案说明分散在 `app.py`、模板和 [i18n.js](e:\MouseScope_gui\static\js\i18n.js) 多处
- 公共页面缺少模板局部件与共享页面骨架，导致改一个视觉细节往往要在多个页面重复修改
- 版本号、模块说明、按钮文案等公共信息缺少单一事实源，后续很容易出现内容不同步

## 3. 设计方向

本次 UI 重构采用 [DESIGN.md](e:\MouseScope_gui\DESIGN.md) 提供的方向，但会做**行为学桌面分析软件的本地化转译**，不直接照搬营销官网排版。

### 3.1 视觉关键词

- 温暖纸张感背景，不走冷蓝科技风
- Serif 标题 + Sans 功能文本的双字体层级
- 高信息密度，但仍保留编辑型页面的呼吸感
- 通过暖色边框、柔和 ring shadow、分层卡片表达结构
- 强调“实验配置工作台”而非“表单堆叠”

### 3.2 应用到 MouseScope 的具体落点

- `base.html` 统一导航、页宽、标题区、按钮层级、页脚视觉
- 上传页做成“实验选择 + 文件导入 + 批量/输出设置 + 手册入口”的统一欢迎入口
- 多视频上传后进入“批量工作台”；单视频模式直接进入对应配置页
- 各实验标定页统一成“单视频配置工作台”：左主画布 + 右配置侧栏 + 顶部步骤导航 + 底部状态条
- 监控页统一成“状态概览 + 实时表格 + 日志 + 下载”四块结构
- 保留当前桌面软件的实用性，不牺牲参数可见性与操作效率

### 3.3 架构关键词

- `Registry-driven`：实验元信息与差异点集中注册，而不是散落在分支里
- `Thin app entry`：`app.py` 只保留 Flask 初始化、公共注册与兼容入口
- `Shared workbench`：配置页共享工作台框架与共同行为，实验只提供自己的差异适配
- `Single source of truth`：版本号、实验名称、手册映射、模板映射、i18n key 尽量集中维护
- `Refactor once, validate continuously`：这轮目标是完整重构，但每一层都配套回归检查，避免“大手术没有监护”

## 4. 统一后的页面框架

### 4.1 统一信息架构

单视频配置页统一为两步或三步框架：

1. `空间标定 / ROI 配置`
2. `参数调试 / 预览`
3. `开始分析`

对于需要体长标定的 TST：

1. `尺度标定`
2. `ROI 配置`
3. `参数调试`

对于 arena/zone 型实验：

1. `Arena / ROI / Zone 配置`
2. `参数调试`

### 4.2 统一布局骨架

- 页面顶部：实验名、简短说明、手册按钮、返回批次按钮（若为批量模式）、步骤导航
- 左侧主区域：当前帧画布 / 调试双画布
- 右侧侧栏：ROI 列表、当前编辑对象、时间窗、检测遮罩、对象角色等
- 底部状态条：已配置 ROI 数、完成度、当前模式、当前点数、当前提示

### 4.3 统一卡片分区

每个配置页都尽量采用以下卡片分区：

- `画布区`
- `当前编辑状态`
- `ROI / Arena / Zone 列表`
- `时间窗设置`
- `检测遮罩设置`
- `检测参数`
- `统计参数`

### 4.4 批量工作台框架

多视频模式不再复用“单视频配置页 + 顶部下拉切视频”的旧结构，而改为独立的批次工作台：

1. `上传完成`
2. `进入批量工作台`
3. `查看每个视频的配置卡片`
4. `点击某一条视频进入单视频配置页`
5. `保存后返回批量工作台`
6. `全部完成后统一开始分析`

批量工作台页面包含以下区块：

- `批次概览区`：实验类型、视频总数、输出目录、全局起止时间、是否生成结果视频
- `批次进度区`：已完成 / 未完成 / 缺项数量，是否允许开始分析
- `共享设置区`：真正属于整个批次的配置项，只在这里显示一次
- `视频卡片区`：每个视频一张卡片，显示文件名、时长、FPS、分辨率、配置状态、缺失项摘要、进入编辑按钮
- `快捷操作区`：复制上一条配置、复制到未完成视频、重置当前视频配置、批次级校验

### 4.5 目标工程结构

为了避免未来继续把新功能堆回单文件，本轮重构后的目标结构应接近下面这种分层：

- `app.py`
  - 仅负责创建 Flask app、注册 Blueprint / 路由组、注册过滤器与全局上下文
- `routes/`
  - `pages.py`：首页、上传页、手册页、批量工作台、配置页、监控页
  - `upload_api.py`：上传、路径验证、会话创建
  - `analysis_api.py`：取帧、调试预览、开始分析、状态、停止分析
  - `results_api.py`：下载、打开目录、结果路径
  - `license_api.py`：许可协议接口
- `services/`
  - `session_store.py`：运行态 session / analysis 管理，批次配置必要时支持磁盘快照
  - `experiment_registry.py`：实验注册表
  - `config_builders.py` 或按实验拆分的 builder 模块：负责 payload 归一化
  - `preview_service.py`：调试预览分发
  - `analysis_factory.py`：分析类实例化分发
- `analysis_sessions/` 或 `core/analysis_sessions/`
  - 每个实验一个 session 类模块，公共逻辑抽成基类
- `templates/partials/`
  - 页头、状态条、工作台卡片、批量卡片、通用步骤条等局部模板
- `static/js/workbench/`
  - 共用画布交互、ROI 列表、时间窗、mask 编辑、批量状态与保存逻辑
- `static/js/pages/`
  - 各页面自己的薄适配脚本

## 5. 交互统一策略

### 5.1 ROI 列表位置统一

- 全部实验的 ROI / arena / zone 配置入口统一放在右侧侧栏
- 不再保留下方单独一整块 ROI 列表的旧布局
- TST 页面将重排为和其它模块同级的“左画布 + 右侧栏”

### 5.2 时间窗交互统一

统一规则：

- 默认显示 `mode` 选择器
- 当 `mode = global` 时，时间输入区域隐藏
- 当 `mode = relative / precise` 时，再展开 `start / end`
- 展开后的帮助文案随模式变化

适用范围：

- TST
- OFT
- NOR
- EPM
- Y-maze

### 5.3 检测遮掩框统一

统一规则：

- “实验统计区域”与“检测允许区域”明确分离
- 有需要的实验都支持额外 detection mask
- detection mask 只影响检测，不改变统计几何

计划处理：

- OFT / NOR：保留现有 detection mask 能力，但重做入口和文案
- EPM / Y-maze：补充 detection mask 编辑能力
  - 默认检测区域跟随 ROI union / zones union
  - 如画面边缘畸变、暗角、支架、噪声明显，可为单个 ROI 增加自定义检测遮罩
- TST：保持现有 ROI 检测逻辑，但评估是否需要单独 mask；若不加，则在计划中明确“本轮不扩展”

### 5.4 批量模式重构

统一规则：

- 多视频上传后，默认进入批量工作台，而不是直接进入 ROI 页面
- 单视频配置页一次只编辑一个视频，不再承担整批视频切换职责
- 批次级共享配置和单视频局部配置明确分层
- 批量分析只能从批量工作台发起，并在发起前做完整预检

目标流程：

1. 上传多个视频后进入批量工作台
2. 用户先看到整批视频的卡片列表和完成状态
3. 点进任意视频卡片，进入该视频自己的 ROI / 参数配置页
4. 保存后返回批量工作台，状态即时更新
5. 所有必填项满足后，才允许从工作台启动批量分析

技术落点：

- 后端分析仍继续使用现有 `per_video_configs` 结构，避免破坏分析主流程
- 前端不再让每个模板各自维护完整的批量编排状态机，而是抽离成统一的批次状态组织层
- 可保留 `/calibrate/<session_id>` 作为兼容入口，但批量模式下应重定向到批量工作台或视频专属配置页
- 单视频页中只保留“返回批次”“当前视频信息”“保存当前视频配置”等和本视频直接相关的交互

同轮一起修正的逻辑债：

- 上传完成后缺少“项目级中间页”的问题
- 缺项校验过晚、只能在开始分析时集中报错的问题
- 批量完成状态不可见、必须靠切换下拉框人工确认的问题
- 各实验模板重复实现批量切换逻辑的问题

### 5.5 后端入口解耦与实验注册机制

统一规则：

- 不再让 `app.py` 同时充当“应用入口 + 业务服务层 + 实验工厂 + 路由聚合器 + 分析类定义文件”
- 实验差异通过统一注册表描述，而不是在多个接口里重复写 `if / elif`
- 调试预览、分析启动、模板选择、手册选择、监控页选择等都从注册表取值

计划处理：

- 建立实验注册表，至少统一这些字段：
  - `experiment_type`
  - `display_name`
  - `manual_module`
  - `calibrate_template`
  - `monitor_template`
  - `debug_preview_handler`
  - `config_builder`
  - `analysis_session_class`
  - `validator`
- 把 [app.py](e:\MouseScope_gui\app.py) 中长链分发改成注册表驱动
- 把各实验 `start_analysis` 的 payload 解析拆到 builder
- 把 session 类拆出 `app.py`，公共逻辑上提为基类

### 5.6 前端共享工作台与 i18n 收口

统一规则：

- 页面结构共用，实验差异通过配置与适配层表达
- 公共交互能力只写一份，不再在多个模板重复拷贝
- 文案、版本信息、实验入口说明尽量有统一来源

计划处理：

- 抽离共享工作台脚本，统一处理：
  - 视频信息加载
  - 批量状态保存
  - ROI 卡片渲染
  - 时间窗展开/隐藏
  - detection mask 编辑流程
  - 调试预览请求
  - 开始分析前校验
- 将通用 UI 片段抽为模板 partial
- 对 [i18n.js](e:\MouseScope_gui\static\js\i18n.js) 做整理，避免版本号、模块说明、公共按钮文案四处漂移
- 让上传页、手册页、批量工作台、配置页都从统一实验元数据中拿到模块信息

### 7.2 代码实施原则

- 优先做“抽公共布局 / 公共组件 / 公共行为”的重构，而不是复制粘贴新模板
- 以“一次性完整重构”为目标，但每一层改动都必须有对应的渲染 / 路由 / smoke 验证
- 前端结构改动后立刻做路由渲染检查
- 涉及 schema 扩展的地方必须和 `app.py` / core 同步检查
- 所有文案新增同步考虑中文编码和 i18n
- 任何从 `app.py` 拆出的模块，都要先保证行为等价，再继续做结构优化
- 每完成一个结构层级，就补最小自动化检查，避免后面只能靠人工记忆回归

## 9. 验收标准

重构完成后，至少满足以下验收项：

- 5 个实验模块在视觉层级上属于同一产品，而不是 5 套拼接页面
- [app.py](e:\MouseScope_gui\app.py) 不再承载大部分业务实现，而是退化为薄入口
- 新增实验时不再需要在多个 API 中手写长分支，而是通过注册表接入
- 共享工作台脚本能覆盖 5 个实验模块的大部分共同行为
- 多视频上传后先进入批量工作台，而不是直接进入 ROI 配置页
- 批量工作台中每个视频都有独立卡片，状态、缺项、入口清晰可见
- 单视频配置页不再需要顶部视频切换下拉框才能完成批量编辑
- 批量模式下已完成的配置在意外关闭应用后仍可被恢复，至少恢复到最近一次显式保存状态
- TST、OFT、NOR、EPM、Y-maze 的 ROI 编辑入口都位于统一位置
- 时间窗输入逻辑一致，`global` 时隐藏，`precise/relative` 时展开
- OFT / NOR 的 detection mask 样式统一
- EPM / Y-maze 具备与统一系统兼容的 detection mask 能力
- 批量模式下每个视频的配置状态可视且不混乱
- 页面中英文切换不出现明显错位、乱码、文案缺失
- 所有已有分析流程和结果下载功能保持正常

## 10. 建议的实施顺序

建议按下面顺序进行，降低回归风险：

1. 先做 `目标目录骨架 + 实验注册表 + 回归基线`
2. 再做 `base + 主题变量 + 上传页`
3. 再做 `批量工作台 + 批次状态流转`
4. 再做 `app.py 拆分 + routes/services/analysis_sessions 落位`
