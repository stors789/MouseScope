🎉 **MouseScope v3.1.0 - TST LIS, Real Video Timebase, Safer Uploads & Release Robustness**

MouseScope `v3.1.0` 是基于 `v3.0.0` 项目工作台版本的一次稳定性与真实实验视频处理更新。

`v3.0.0` 的重点是把 MouseScope 从单次分析工具扩展为支持项目、组别、小鼠、视频和结果管理的实验工作台。
`v3.1.0` 则进一步聚焦在 **悬尾实验 TST 识别稳定性**、**真实视频时间轴可靠性**、**用户入口防呆** 和 **打包发布可靠性**。

本版本将 **TST 悬尾实验** 默认主路径升级为微小挣扎优化的 `LIS` 逻辑。
新的判定路径不再只依赖单一像素变化阈值，而是综合轮廓残差、形态变化、外周活动、高频变化和状态连续性，更适合处理轻微挣扎、摆动和边界状态。旧版逻辑仍被保留为兼容开关，便于复核和回归对照。

本版本新增了更完整的 **视频元数据与时间轴处理**。
MouseScope 现在会结合 OpenCV、`ffprobe/ffmpeg` 和 PTS 时间戳信息，优先使用真实视频时间轴，无法取得时再回退到均匀 FPS 时间轴。这对可变帧率视频、录屏视频、FPS 元数据不准确的视频尤其重要。

分析结果也变得更容易复核。
多个实验模块会记录时间轴来源、采样帧率、帧步长、空间缩放和实际处理样本数，用户可以更清楚地判断结果是否来自有效解码和有效采样。

本版本还加强了 **运行时防护**。
如果视频元数据看起来正常，但实际分析循环没有成功解码任何帧，系统会把任务标记为错误，而不是生成一个看似完成但没有有效数据的空结果。

用户入口也进行了实际使用层面的修复。
快速分析上传页现在会真正请求后端验证本机路径，提前发现不存在路径、空文件夹和不支持的视频格式。非法 FPS、负数时间窗、结束时间早于开始时间等输入也会在分析开始前被拦截。

任务中心和许可协议流程也更稳。
任务中心新增分页式“加载更多”，并避免非法 `limit` 参数导致后端错误。软件重启后，如果浏览器本地已经记录用户同意许可协议，后端 session 会自动同步，并回到用户原本要打开的页面。

最后，本版本补齐了 **PyInstaller 打包配置**。
新增的服务模块、TST 算法模块、时间轴模块、项目路由和可选 `ffprobe` 收集逻辑都已同步到 `MouseScope.spec` 与构建文档，降低发布包漏模块的风险。

## 相比 v3.0.0 的主要差别

- `v3.0.0` 新增项目工作台；`v3.1.0` 在此基础上增强真实视频分析稳定性
- `TST` 默认启用微小挣扎优化的 `LIS` 主算法
- 保留 `TST` legacy 旧逻辑作为兼容和复核路径
- 新增 `services/video_metadata.py`，改进 FPS、帧数、时长和手动 FPS 覆盖处理
- 新增 `services/video_timebase.py`，优先使用 PTS 时间戳处理真实视频时间轴
- 多个实验模块接入统一时间轴、采样和结果摘要字段
- 分析运行时新增 0 解码帧防护，避免空结果伪成功
- 批量分析进度聚合更准确，减少并行批处理时进度跳动
- 快速分析上传页新增后端真实路径验证
- 上传入口提前拦截非法 FPS、负数时间窗和无效起止秒数
- 许可协议同意状态在重启后可自动同步并回到原页面
- 任务中心新增“加载更多”和非法参数保护
- 草稿复制/重置等 API 增强非法索引保护
- 打包配置补齐新模块 hidden imports
- 打包流程支持可选收集 `ffprobe`，提升可变帧率视频支持
- 新增项目健康检查、视频元数据、分析运行时和用户入口回归测试
- 更新 README、引用信息、系统架构文档和发布文档至 `v3.1.0`
- 保留 `v3.0.0` 的项目工作台、快速分析、新手引导和 6 类实验模块
- 继续保持本地桌面 `GUI` 使用方式，无需编程和云端账号

🎉 **MouseScope v3.1.0 - TST LIS, Real Video Timebase, Safer Uploads & Release Robustness**

MouseScope `v3.1.0` is a stability and real-video processing update built on top of the `v3.0.0` Project Workspace release.

Version `v3.0.0` expanded MouseScope from a quick analysis tool into a project-oriented experiment workspace for managing projects, groups, animals, videos, and results.
Version `v3.1.0` focuses on **Tail Suspension Test stability**, **real video timebase accuracy**, **safer user entry points**, and **more reliable packaging**.

The **Tail Suspension Test, TST** workflow now uses the subtle-struggle optimized `LIS` logic as the default primary path.
Instead of relying on a single pixel-change threshold, the new path combines contour residuals, shape changes, peripheral activity, high-frequency cues, and state continuity. This makes subtle struggling, swinging, and boundary states easier to score and review. The legacy logic remains available as a compatibility and comparison option.

This release adds more complete **video metadata and timebase handling**.
MouseScope now combines OpenCV, `ffprobe/ffmpeg`, and PTS timestamp information. It prefers real video timestamps when available and falls back to uniform FPS timing only when needed. This is especially important for variable-frame-rate videos, screen recordings, and videos with unreliable FPS metadata.

Outputs are also easier to audit.
Several assay modules now record timebase source, sampling FPS, frame stride, spatial scale, and actual processed sample counts, making it clearer whether results came from valid decoding and valid sampling.

Runtime safeguards have been strengthened.
If metadata reports frames but the analysis loop decodes zero usable frames, MouseScope now marks the task as failed instead of producing an apparently successful empty result.

User-facing entry points have also been improved.
The Quick Analysis upload page now validates local paths through the backend, catching missing paths, empty folders, and unsupported formats before setup begins. Invalid FPS values, negative time windows, and reversed start/end seconds are rejected before analysis starts.

Task Center and license handling are more robust.
Task Center now supports a load-more flow and protects the backend from invalid `limit` parameters. After restarting the app, a browser that already accepted the license can sync the server session automatically and return to the originally requested page.

Packaging metadata has been updated as well.
New service modules, TST algorithm modules, timebase modules, project routes, and optional `ffprobe` collection are now reflected in `MouseScope.spec` and the build guide, reducing the risk of missing modules in release builds.

## Main differences from v3.0.0

- `v3.0.0` introduced Project Workspace; `v3.1.0` improves real-video analysis robustness on top of it
- Enabled the subtle-struggle optimized `LIS` path as the default `TST` algorithm
- Kept the `TST` legacy path for compatibility and review
- Added `services/video_metadata.py` for improved FPS, frame-count, duration, and manual FPS override handling
- Added `services/video_timebase.py` to prefer PTS timestamps for real video timing
- Connected multiple assay modules to shared timebase, sampling, and summary metadata
- Added a zero-decoded-frame runtime guard to avoid empty-result false success
- Improved batch-progress aggregation for parallel analysis
- Added backend local-path validation for Quick Analysis uploads
- Rejected invalid FPS, negative time windows, and invalid start/end seconds before analysis
- Synced accepted license state after app restart and returned users to the original page
- Added Task Center load-more behavior and invalid parameter protection
- Hardened draft copy/reset APIs against invalid indices
- Updated PyInstaller hidden imports for new modules
- Added optional `ffprobe` collection support for release builds
- Added project-health, video-metadata, runtime, and user-entrypoint regression tests
- Updated README, citation metadata, system architecture docs, and release notes to `v3.1.0`
- Kept the `v3.0.0` Project Workspace, Quick Analysis, Guided Tour, and all six assay modules
- Still designed as a local desktop `GUI` application with zero coding required
