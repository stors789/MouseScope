Y 迷宫完整操作手册

本手册覆盖 Y 迷宫自发交替实验的实验逻辑、采集要求、三角中心区 + 3 条臂的手动画区、检测遮罩、时间窗、主要参数，以及结果字段的解释方式。

中心区 + 3 臂手动画区 自发交替统计 入臂深度判定 检测遮罩可选 track / summary / bins

主要统计什么

统计各臂停留时间、总入臂数、交替次数、交替机会数和交替率，同时保留距离与速度指标。

什么叫交替

连续三次入臂访问了三个不同臂，才会被记为一次自发交替，因此总入臂数过低时需要谨慎解释交替率。

为什么也有入臂深度

只有质心进入手画臂区更深的位置才记为一次入臂，可减少中心区边缘来回抖动带来的重复计数。

1总览

Y 迷宫模块用于分析小鼠在中心区与 Arm A / B / C 之间的空间切换，并计算自发交替率。最关键的是把中心区和三条臂的边界画准，再确认入臂计数稳定。

  • 交替率常定义为：交替次数 / (总入臂数 - 2) × 100%。
  • 如果总入臂数过低，交替机会数会不足，交替率就不稳定，解释时必须结合 total_arm_entries 一起看。
  • 系统会分别统计中心区停留和三条臂的停留时间，便于识别“主要停在中心区”的视频。

2采集要求

  • 优先使用稳定俯视或接近俯视的固定机位，不要在录制中移动相机。
  • 中心区和三条臂都应完整可见，尽量避免某条臂被裁切或被反光遮挡。
  • 保持鼠体和地面有明显亮度对比，减少阴影和局部高亮。
  • 如果臂外背景或实验台边缘容易误检，建议优先使用检测遮罩。

3上传与时间范围

  • 上传页中的开始秒数和结束秒数是默认统计时间窗；ROI 设为“跟随全局”时会直接沿用。
  • FPS 元数据不可靠时建议手动覆盖，否则距离、速度和潜伏时间可能不准确。
  • 多视频模式下会先进入批次页面，再逐条完成每个视频的 Y 迷宫设置。

4三角中心区与时间窗

每个 ROI 对应一个完整 Y 迷宫，只有中心区、Arm A、Arm B、Arm C 全部完成后，才会进入预览和正式分析。

中心区 3 点，三条臂各 4 点

  • 中心区使用 3 个点绘制三角形交汇区；Arm A / B / C 三条臂各使用 4 个点。系统会自动归一化点序，所以关键是边界位置是否准确。
  • 中心区建议贴合三臂真实交汇形成的三角形范围；Arm A / B / C 建议按实际可活动区域绘制。

真实尺寸与厘米换算

  • 请填写臂长和臂宽，系统会据此估算 cm_per_px_est。
  • 这个尺度会影响距离、速度和运动阈值。

检测遮罩 detection mask

  • 遮罩只限制允许检测前景的区域，不会改变中心区和三条臂的统计边界。
  • 如果不单独绘制，系统默认使用三角中心区与三条臂区域的并集作为检测区域。
ROI 时间窗模式
模式含义推荐场景
global跟随上传页的全局开始 / 结束时间。大多数标准 Y 迷宫分析。
precise按视频绝对时间指定开始 / 结束秒数。只分析固定片段时。

完整 ROI 才会被统计

如果某个 ROI 只有部分区域完成，系统不会把它纳入预览或正式分析。

6结果字典

Y 迷宫会导出结果视频、逐帧轨迹 CSV、summary CSV、分箱 CSV，以及每个 ROI 的热图和轨迹图。

*_analyzed.mp4

叠加手画区域、入臂深度触发区、当前区域标签、入臂事件、交替事件和轨迹的结果视频。

*_track.csv

逐帧记录区域、速度、累计距离、入臂事件和最近入臂序列。

*_summary.csv / *_bins.csv

输出核心统计结果和固定时间箱汇总。

*_track.csv
字段含义解读建议

*_summary.csv

7批量流程

Y 迷宫的批量模式是“每个视频各自配置，再统一运行”。不要只画第一个视频就直接开始整批分析。

  1. 上传多个 Y 迷宫视频，并设置全局时间窗、FPS 覆盖和输出目录。
  2. 逐条打开视频卡片，完成当前视频的三角中心区、三条臂、检测遮罩、时间窗和参数设置。
  3. 保存当前设置并返回批次页面，再继续处理下一条视频。
  4. 确认所有卡片都显示为已完成后，再统一开始批量分析。

8常见问题与排错

  • 交替率异常高或异常低：先检查中心区和三条臂是否画得过窄、重叠或空隙过大。
  • 入臂数明显偏高：先复核结果视频中的 arm_entry_event，再调整 entry_depth_ratio，并确认中心区边界没有和臂区重叠。
  • 某一条臂几乎没有访问：先排除该臂边界识别差、阴影或高亮背景干扰。
  • 总入臂数很低：解释交替率前，先确认视频本身是否存在探索不足或检测漏检。

什么时候一定要人工复核

如果结果将用于正式统计或论文结论，建议至少抽查结果视频，尤其是中心区边界识别不稳、入臂数过低或交替事件明显与肉眼不一致的视频。

Complete Y-Maze Manual

This manual covers assay logic, recording requirements, triangular-center plus three-arm drawing, detection masks, time windows, key parameters, and result interpretation for spontaneous alternation.

Center + 3 manual arms Spontaneous alternation Entry-depth gating Optional mask track / summary / bins

What is quantified

The module measures per-arm occupancy, total arm entries, alternation count, alternation opportunities, alternation rate, distance, and speed.

What counts as an alternation

An alternation is counted only when three consecutive entries visit three different arms, so low entry counts make alternation rate unstable.

Why entry depth still matters

An arm entry is counted only after the centroid moves deeper into the arm, reducing repeated counting near the center junction.

1Overview

  • The module quantifies switching among the center and Arm A / B / C, then computes spontaneous alternation.
  • Alternation rate is commonly defined as alternation count divided by total arm entries minus two.
  • Very low entry counts make alternation rate unstable and should be interpreted cautiously.

2Recording requirements

  • Use a stable top view or near-top view.
  • Keep the center and all three arms visible without heavy clipping.
  • Maintain strong contrast between the mouse and maze floor while minimizing glare and shadow.
  • If background outside the arms is frequently detected, prefer a detection mask.

3Upload and timing

  • Global start and end time define the default analysis window.
  • Override FPS when metadata is unreliable because distance, speed, and latency depend on it.
  • Multi-video sessions open the batch page first so each video can be configured independently.

4Triangle center and timing

  • Each ROI represents one full Y-maze with center, Arm A, Arm B, and Arm C.
  • The center is defined by 3 clicks as a triangle junction, while Arm A / B / C each use 4 corner clicks. Point order is normalized automatically.
  • Enter arm length and arm width so MouseScope can estimate cm_per_px_est.
  • The detection mask limits where foreground detection is allowed but does not redefine the statistical zones.

6Outputs

  • *_analyzed.mp4: annotated video with hand-drawn zones, entry-depth trigger regions, zone labels, entry events, alternation events, and trajectory overlay.
  • *_track.csv: frame-level records of zone, speed, cumulative distance, arm-entry events, and recent entry sequence.
  • *_summary.csv: one-row-per-ROI summary table with the main Y-maze metrics.
  • *_bins.csv: fixed-width temporal bins for occupancy, entries, alternations, and distance.
  • entry_reset_center_s in summary records the stable-center reset duration used by the same-arm entry lock.

7Batch workflow

  1. Upload multiple Y-maze videos and define global timing, FPS override, and output folder.
  2. Open each video card and finish the triangular center, three arms, mask, timing, and tuning for that video.
  3. Save the current setup and return to the batch page before moving to the next video.
  4. Only start analysis after all cards are marked complete.

8Troubleshooting

  • Implausibly high or low alternation rate: check whether the center and arm zones are too narrow, overlapping, or separated by large gaps.
  • Entry counts too high: review arm_entry_event in the annotated video, then tune entry_depth_ratio and confirm that center-arm boundaries do not overlap.
  • One arm is rarely visited: check that the arm boundary is visible and not dominated by glare or shadow.
  • Very low total entries: confirm that exploration is genuinely low rather than missed by detection.
